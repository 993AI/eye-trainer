# 功能升级 1.1：直接式、渐变式与色温训练

## 1. 升级目标

在现有 macOS 练眼软件的自动训练基础上，增加：

- 直接式变化
- 渐变式变化
- 色温控制
- 亮度与色温同步训练

本次升级保留现有的菜单栏、浮动状态窗、全局快捷键、XPC 计时和屏幕唤醒恢复能力，不改变现有用户的基本使用方式。

## 2. 功能定位

训练功能由两个维度组成：

| 维度 | 可选项 |
|---|---|
| 变化对象 | 仅亮度、仅色温、亮度 + 色温 |
| 变化方式 | 直接式、渐变式 |

亮度和色温使用同一个训练时间轴，避免两个计时器产生漂移。

## 3. 变化方式

### 3.1 直接式

在最小值和最大值之间瞬间切换：

```text
低值 → 高值 → 低值 → 高值
```

亮度训练中表现为明暗跳变，色温训练中表现为暖色与冷色跳变。

建议：

- 低值和高值各保持半个完整周期
- 到达切换点时立即改变目标值
- 直接式应设置合理的最小周期，避免过快闪变

### 3.2 渐变式

在最小值和最大值之间连续变化：

```text
低值 → 平滑变高 → 平滑变低 → 低值
```

亮度和色温都采用连续插值，避免明显的阶跃变化。

## 4. 周期定义

继续使用当前项目中 `cycleSeconds` 的“完整周期”语义：

```text
低值 → 高值 → 低值
```

因此：

- 渐变式：前半周期从低值变到高值，后半周期从高值变回低值
- 直接式：前半周期保持低值，切换到高值后保持半个周期，再切回低值

例如完整周期设置为 6 秒，则直接式每 3 秒切换一次。

原 Windows 软件中的“间隔”表示两次极值切换之间的时间。如需复刻原软件体验，可将完整周期设置为原间隔的两倍。界面应明确标注“完整周期”，避免歧义。

## 5. 训练对象设置

训练设置中增加“变化对象”：

### 5.1 仅亮度

仅按照亮度范围进行训练，色温保持当前或中性色温。

### 5.2 仅色温

亮度保持当前值，色温在暖色和冷色之间变化。

### 5.3 亮度 + 色温

亮度和色温使用同一时间轴、同一变化方式同步变化。

第一版不建议为亮度和色温分别设置独立速度，以减少使用复杂度和计时漂移风险。后续如有需求，再增加独立参数。

## 6. 亮度设置

保留现有设置：

- 最小亮度
- 最大亮度
- 完整周期
- 训练时长
- 无限时训练

继续使用当前项目默认值：

- 最小亮度：15%
- 最大亮度：90%
- 完整周期：3 秒

直接式应避免使用过短周期。界面可以提示用户，过快的明暗切换可能影响舒适度。

## 7. 色温设置

新增：

- 最低色温
- 最高色温
- 当前色温
- 色温训练开关或训练对象选择

建议范围：

| 设置项 | 建议值 |
|---|---:|
| 可调范围 | 1000K–10000K |
| 默认最低色温 | 3000K |
| 默认最高色温 | 8000K |
| 中性色温 | 6500K |

1000K 和 10000K 属于较强的色温效果，建议保留高级调节能力，但不作为默认范围。

## 8. 色温实现原则

不直接照搬原 Windows 软件的色温算法。

原软件虽然提供色温滑块，但三个 RGB 通道使用相同缩放公式，实际并没有真正改变白平衡，更接近第二个亮度参数。

macOS 版本应实现真正的 RGB 色温变化：

- 6500K：保持中性色
- 低于 6500K：减少蓝色比例，画面偏暖
- 高于 6500K：增加蓝色比例，画面偏冷

亮度和色温应分开计算：

```text
最终红色通道 = 亮度系数 × 色温红色系数
最终绿色通道 = 亮度系数 × 色温绿色系数
最终蓝色通道 = 亮度系数 × 色温蓝色系数
```

色温计算应尽量保持整体亮度稳定，避免用户感知到的色温变化同时变成明显的明暗变化。

## 9. 屏幕输出方案

### 9.1 支持 Gamma 调节的屏幕

沿用现有的 Gamma 控制方案，在每个显示器上保存原始 Gamma 参数，并根据亮度和色温共同生成 RGB 通道参数。

停止训练、退出程序、显示器变化或唤醒恢复时，恢复原始 Gamma。

### 9.2 不支持 Gamma 调节的外接屏

沿用当前的覆盖层降级方案：

- 黑色覆盖层控制亮度
- 暖色或蓝色半透明覆盖层控制色温

覆盖层应保持鼠标穿透，并为每个显示器单独维护。显示器拔插、分辨率变化和 Space 切换后需要重新创建或调整覆盖层。

## 10. 运行时数据流

```text
训练设置
    ↓
AppViewModel
    ↓
训练计时器与曲线计算
    ↓
当前亮度 + 当前色温 + 训练进度
    ↓
ScreenDimmingController
    ↓
Gamma 输出或覆盖层输出
```

XPC 服务继续承担训练计时和曲线计算。每次状态更新需要同时包含：

- 当前亮度
- 当前色温
- 已运行时间
- 剩余时间

XPC 不可用时，本地降级计时器必须使用完全相同的计算规则，确保训练不会中断或突然跳变。

## 11. 界面调整

### 11.1 训练设置页

增加以下区域：

1. 变化对象
2. 变化方式
3. 色温范围
4. 色温默认值

现有的亮度范围、周期和训练时长设置继续保留。

### 11.2 浮动状态窗

训练时显示：

```text
亮度：65%
色温：5200K
模式：渐变式
```

仅亮度训练时可以隐藏色温信息；仅色温训练时应显示当前亮度保持值。

### 11.3 手动控制窗口

增加：

- 手动亮度滑块
- 手动色温滑块
- 恢复默认按钮

手动模式下，用户可以分别调节亮度和色温，不启动自动训练时间轴。

## 12. 设置兼容与默认值

已有用户升级到 1.1 时：

- 默认训练对象：仅亮度
- 默认变化方式：渐变式
- 现有亮度范围保持不变
- 现有周期保持不变
- 色温默认值：6500K
- 色温范围默认使用 3000K–8000K

这样升级后不会改变原有亮度训练效果。

## 13. 生命周期与异常处理

继续支持现有逻辑：

- 停止训练时恢复原始显示状态
- 程序退出时恢复原始显示状态
- 锁屏前保存显示基准
- 唤醒后延迟恢复亮度和色温
- 显示器拔插后重新绑定输出
- 屏幕配置变化后重新捕获 Gamma
- XPC 断开时切换本地降级计时器
- XPC 恢复后交还训练控制权

亮度和色温恢复必须作为一个整体执行，避免只恢复亮度而遗留色温偏移。

## 14. 分阶段实施建议

### 第一阶段：变化方式

- 增加直接式和渐变式配置
- 先应用到亮度训练
- 保持现有三种曲线兼容
- 确认周期和切换时间语义

### 第二阶段：色温引擎

- 增加真实的 RGB 色温计算
- 支持 Gamma 输出
- 支持亮度与色温合成
- 增加本地降级路径

### 第三阶段：界面与多显示器

- 增加色温设置界面
- 增加手动色温控制
- 更新浮动状态窗
- 完善外接屏、锁屏、唤醒和显示器拔插场景

### 第四阶段：验证与调优

- 验证直接式切换时间
- 验证渐变式连续性
- 验证亮度和色温同步
- 验证停止后完整恢复
- 验证 XPC 断开和恢复
- 验证多显示器输出一致性
- 验证 HDR、Night Shift、True Tone 等系统显示功能下的表现

## 15. 验收标准

功能升级完成后应满足：

1. 用户可以选择亮度、色温或两者同时训练。
2. 用户可以选择直接式或渐变式。
3. 直接式在设定的切换点瞬间改变目标值。
4. 渐变式在完整周期内连续变化，不出现明显跳变。
5. 亮度和色温在同步训练时保持同一相位。
6. 手动模式可以分别调节亮度和色温。
7. 停止、退出、锁屏唤醒和显示器拔插后，显示状态能够恢复。
8. XPC 断开时，本地降级逻辑与 XPC 逻辑表现一致。
9. 升级已有配置后，原有亮度训练行为不发生意外变化。

## 16. 推荐结论

建议保留原 Windows 软件的“直接式/渐变式”交互概念，但不要复制其有缺陷的色温算法。

macOS 版本应以现有的 Gamma 与覆盖层架构为基础，实现真正的 RGB 色温变化，并使用一个统一训练时间轴同步驱动亮度和色温。这样既能复刻原软件的主要体验，又能保持当前项目在多显示器、锁屏恢复和 XPC 容错方面的优势。
