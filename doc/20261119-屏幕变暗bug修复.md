# 屏幕变暗 Bug 修复方案

日期：2026-11-19  
适用程序：EyeTrainer

## 一、问题现象

程序运行一段时间后，锁屏再解锁，屏幕的明暗变化仍在继续，程序显示的亮度百分比也正常，但实际亮度范围整体变暗。

典型表现是：

- 锁屏前亮度变化正常；
- 解锁后训练曲线仍然运行；
- 程序显示的最高亮度数值没有异常；
- 屏幕实际最高亮度变成了锁屏时较暗的亮度；
- 再次锁屏、解锁不能恢复；
- 退出并重新打开程序后恢复正常。

## 二、问题结论

这是显示输出基准缓存错误导致的程序 Bug，不是亮度百分比计算错误，也不是训练曲线停止。

锁屏期间 macOS 可能会临时压暗显示器的 Gamma/显示传输曲线。程序解锁时如果把这条临时暗态曲线当成正常基准，后续所有亮度值都会在较暗的基准上重新缩放。

因此，程序内部的亮度数值仍然正确，但屏幕实际可达到的最高亮度被压低了。

## 三、为什么重复锁屏解锁仍不能恢复

程序当前会在内存中保留显示器的 Gamma 基准。一旦第一次解锁时错误地保存了暗态曲线，后续锁屏和解锁会继续复用这条错误基准。

这会形成以下结果：

1. 第一次解锁时捕获到错误的暗态基准；
2. 后续训练都基于该基准输出；
3. 再次锁屏时保存的仍然是错误基准；
4. 再次解锁后继续使用错误基准；
5. 只有退出程序时，内存缓存被清空并执行完整恢复，屏幕才恢复正常。

## 四、修复目标

修复后应满足以下目标：

- 解锁后不再把临时暗态当成正常基准；
- 屏幕实际亮度范围与程序显示的百分比一致；
- 重复锁屏、解锁可以稳定恢复；
- 不需要退出并重新打开程序；
- 自动训练和手动调节都能恢复；
- 拔插显示器或显示器数量变化后仍能恢复；
- 发生恢复失败时程序可以自行修复，而不是持续使用错误状态。

## 五、修复方案

### 1. 保存锁屏前的有效基准

锁屏或会话失活前，保存每块显示器已经确认过的正常 Gamma 基准。

保存的基准必须与当前显示器 ID 绑定，不能只保存一份全局基准。

### 2. 解锁后禁止立即采集当前曲线

解锁初期 WindowServer 可能仍处于显示恢复阶段。此时不得把当前屏幕曲线直接当作新的正常基准。

解锁流程应先暂停亮度输出，等待系统显示服务稳定后再恢复。

### 3. 优先恢复锁屏前的基准

解锁后，优先使用锁屏前保存的基准恢复 Gamma，再根据当前训练状态重新应用亮度和色温。

即使解锁瞬间屏幕仍然较暗，也不能直接重新采集这条暗态曲线。

### 4. 增加完整重置流程

出现以下情况时，应废弃当前缓存基准并执行完整重置：

- 解锁后实际最高亮度明显低于设定值；
- 没有可用的锁屏前基准；
- 显示器 ID 发生变化；
- Gamma 恢复失败；
- 显示器数量发生变化；
- 连续两次唤醒恢复结果异常。

完整重置流程为：

1. 停止当前亮度输出；
2. 恢复已知的正常 Gamma 或系统显示状态；
3. 移除并隐藏所有亮度遮罩窗口；
4. 等待显示器和 WindowServer 稳定；
5. 重新确认每块显示器的有效基准；
6. 应用当前训练亮度和色温；
7. 重新开始训练输出。

### 5. 增加多阶段唤醒恢复

唤醒恢复不应只依赖单个固定时间点。建议分为几个阶段：

- 第一阶段：暂停输出并清理旧的显示后端；
- 第二阶段：等待系统恢复并应用锁屏前基准；
- 第三阶段：检查显示器布局和实际输出状态；
- 第四阶段：必要时重置并重试；
- 最后阶段：确认正常后清除临时恢复状态。

### 6. 显示器变化单独处理

如果锁屏期间拔掉或接入显示器：

- 保留仍存在显示器的旧基准；
- 对新显示器等待稳定后单独采集基准；
- 不要因为一块屏幕变化而重新采集所有屏幕；
- 重新绑定后再统一应用当前训练状态。

### 7. 停止和重新开始时增加自检

停止训练、重新开始训练和训练完成时，都应确认显示输出已经恢复或重新绑定。

重新开始训练不能只重新启动计时器，还要确认当前 Gamma/遮罩没有残留暗态。

## 六、验证标准

修复后需要验证以下场景：

1. 单屏运行训练，锁屏后解锁；
2. 双屏运行训练，锁屏后解锁；
3. 锁屏时正处于最低亮度；
4. 锁屏时正处于中间亮度；
5. 锁屏时正处于最高亮度；
6. 连续锁屏、解锁 5 次以上；
7. 锁屏期间拔掉一块显示器；
8. 解锁后重新接入显示器；
9. 自动训练模式恢复；
10. 手动亮度模式恢复；
11. 同时启用色温变化时恢复；
12. 停止后重新开始训练；
13. XPC 服务重连后恢复。

每个场景都应满足：

- 亮度百分比显示正常；
- 实际最低亮度和最高亮度范围正常；
- 不需要退出程序；
- 不出现持续闪烁、忽明忽暗或单屏不同步。

## 七、临时解决办法

在修复版本发布前，如果解锁后屏幕亮度范围明显变小，退出并重新打开 EyeTrainer 可以清除错误缓存并恢复显示。

## 八、验收结论

本问题的验收重点不是“程序数值是否变化”，而是“解锁后屏幕实际可达到的亮度范围是否恢复”。只有实际最高亮度、最低亮度和训练曲线都恢复正常，才算修复完成。
